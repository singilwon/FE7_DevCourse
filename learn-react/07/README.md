### useReducer ()

- 상태관리 대표적
- useReducer() vs useState()
- useState()
  - 장점 : 직관적이고 문법이 쉬움
  - 단점 : 상태 업데이트 로직이 컴포넌트 내부에 흩어지기 쉽다.
- useReducer()
  - 장점 : 상태 업데이트 로직이 한 곳에 몰려있음
  - 단점 : 문법이 어려움
  - 복잡한 상태 관리를 할 때 사용한다
- const [상태변수, 액션발생함수] = useReducer(리듀서함수, 초깃값) 모양으로 시작
- 리듀서 함수 : 상태 업데이트 로직이 담겨 있는 함수
  - 리듀서 함수의 매개변수는 내 마음대로 지을 수 있음, 대신 전달되는 값은 정해져 있음
  - 첫 번째는 state값, 두 번째는 action값의 매개변수가 들어감
  - state는 초깃값의 type을 정해주면 됨
  - reducer 함수는 한 개의 return 값이 무조건 있어야 함(나중에 상태값 변경시키려고 하면), 관례상 조치 안 할거면 그냥 지금 값(state)를 반환함

#### 정리

- [상태변수, 액션발생함수] 에서 상태변수는 말 그대로 상태변수
- 액션발생함수는 useReducer(reducer,0) 에서 reducer 함수를 발생시키는 것
- reducer는 함수인데, 첫 매개변수는 상태변수를 받고, 두 번째 매개변수는 액션발생함수로 함수를 실행시킬 때 넘겨주는 값이 들어온다
- 마지막 0은 초기 상태변수 값, 마음대로 바꿀 수 있음
- 액션발생함수로 값을 넘겨주면 reducer 함수에서는 그 값이 함수 내에서 어떤 코드를 실행시켜주는 값이라고 판단하도록 하고 그 값이 맞다고 판단하면, 상태변수를 변경시키도록 만드는 것

### 리렌더링

- 원래는 처음 한 번만 렌더링 되지만
- 상태가 변경될 때만 그에 따른 리렌더링이 진행됨
- 리렌더링하게 되면 컴포넌트 자체가 다시 리렌더링이 되어서 일반 변수는 계속 다시 0으로 초기화 되지만, useState 같은 것들은 내부적으로 초기화되지 않도록 만들었다
- 리렌더링 될 때 그 컴포넌트부터 연관된 하위 컴포넌트들까지 다 리렌더링 된다, 컴포넌트의 하위 컴포넌트의 하위 컴포넌트까지 그 밑으로 다 리렌더링 되지만, 만약 중간에 하위 컴포넌트에서만 리렌더링 하면 그 위에 부모 컴포넌트는 리렌더링 X

#### 컴포넌트 최적화

- 부모 리렌더링 하나만 하고 싶은데 하위 컴포넌트들이 같이 리렌더링 되니깐, 컴포넌트 최적화를 통해 중간에 리렌더링을 막는 것이다.
- 방법 : 컴포넌트 메모이제이션을 하면 됨
- 메모이제이션 : 한 번 계산한 결과를 저장(cache)해 두었다가 같은 입력이 들어오면 다시 계산하지 않고 계산된 결과를 재사용하는 방식
- function 컴포넌트 이름 대신에 React.memo(function 컴포넌트 이름 및 함수 내용들) 이런 식으로 감싼다
- 컴포넌트 메모이제이션이 풀리는 순간
  - 컴포넌트에 전달된 props가 변경되면 메모이제이션이 풀림
  - 자기 자신의 상태가 변경되면 메모이제이션이 풀림
- 모든 컴포넌트를 메모이제이션 하지 않는 이유 : react.memo 자체가 연산 비용이 높기 때문에 남발하면 오히려 성능이 떨어질 수 있음
- 최적화 자체는 가장 마지막에, 문제가 되었을 경우에 실행

#### useCallback

- 함수가 메모이제이션이 됨
- 참조변수인 콜백함수에 쓰는 것(콜백함수를 ()로 묶고 마지막에 [](의존성 배열)를 씀)
- 의존성 배열에 의해서 풀리지 않는 이상 메모이제이션이 계속 됨

#### useMemo

- 값을 메모이제이션 함
- 복잡한 값을 연산하는 게 들어가 있다면, 그때 써주는 것
- 첫 번째 매개변수는 콜백, 두 번째는 의존성 배열
- useMeMO(()=> 값을 연산하는 함수,의존성배열[])
- 한 번 이렇게 계산된 값은 또 리렌더링 될 때 다시 계산하지 않음
- 만약에 의존성 배열에 어떤 변수를 넣으면, 그 값이 변결될 때마다 다시 메모이제이션이 풀리고 계산을 하게 됨

#### Context API

- 방법
  1. 컨텍스트객체를 생성해야함 -> createContext
  2. 컨텍스트의 범위를 지정해야 함 -> 생성 컨텍스트 이름으로 하는 요소 사이에 범위 지정
  3. 데이터를 공급 -> 컨텍스트객체에 value 속성 사용
  4. 사용
- const {내가 받고싶은 값의 이름} = useContext(컨텍스트 객체)!;
- createContext 한 변수는 export 해야지 다른 곳에서 쓸 수 있음

  - 마지막에는 undefined 때문에 !(널 아님 보장) 넣은 것, 이렇게 해서 전역상태 관리에서 값을 가지고 올 수 있음
