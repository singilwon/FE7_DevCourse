## 반복 렌더링과 이벤트, 리액트 훅

### 반복 렌더링

- 배열을 XML에 출력해보면 순서대로 하나씩 나옴
  - XML에서 {} 안에 배열 변수 쓰면 순서대로 나오는 것
- 요소를 반복 렌더링 하려면 그 요소를 가공해서 가공된 값이 포함된 배열로 만들어주면 된다는 생각, 그리고 그 배열을 표현식으로 출력하면 되겠다는 생각
- return 안에서는 for문은 못 쓰기 때문에 밖에서 쓰고 push 한 다음에 그걸 반복 렌더링 해줘야함
  - 불편하기 때문에 map 메서드 써주는 게 좋음
- react는 mapping이 안되기 때문에 key라는 것을 써야 함
  - mapping이 안 된다는 것은 출력이 제 자리를 못 찾는다고 대충 생각, input에 친 것이 친 input에 남아있지 않고 새로 생성한 곳에 계속 남아있는 것, 그래서 key로 고유한 값을 줘서 인식할 수 있게 해주는 것
  - 뒤에 새로운 값을 붙여주면 index를 써도 상관 없지만, 앞에 쓰면 index를 키 값으로 사용하면 안되고 item값을 사용하던지 해야 함
- 배열 내에 객체가 여러가지 있어도 반복 렌더링 가능
  그래서 그걸 이용해서 객체 내에 id 부분을 key에 넣고 하면 고윳값도 생김

### 이벤트

- onClick 이런 것들을 씀 (카멜케이스 표기법으로)
- {} 안에 감싸서 표기
- onClick = {handleClick()} 이런 식으로 쓰면 렌더링 되자마자 바로 호출되기 때문에, 2번 이상 호출이 될 수 있어서 바로 호출하게는 쓰지 않음
  - 1번째 방법은 handleClick 이런 방법으로 참조만 하게 함
  - 2번째 방법은 화살표 함수로 () => handleClick() 이런 방식으로 함
  - 만약 매개변수를 전달해야 되는 상황이면 2번째 방법을 써야 함
- props로 넘겨주기도 가능, 대신 매개변수 있는지 없는지 잘 보고

#### 이벤트 객체

- 특정한 이벤트들이 모여있는 객체
- js에서 e, 즉 event 매개변수가 평소에도 이벤트에는 계속 넘어와서 e.target.style같은 게 가능해짐
- 근데 매개변수가 넘어오는 이벤트이면 넘어오던 event가 넘어오지 않음
  - 되기는 하지만, react 자체에서 동일하게 다 쓸 수 있도록, react 자체에서 오리지널 event 자체를 가공해서 만든 synthentic event 느낌임, 안 쓰는 게 좋다는 것 같음
- 방법은? onClick 자체 매개변수에 들어옴, 그래서 그 매개변수 e를 이벤트 발생할 때 선언되는 함수에 매개변수로 던져주면 됨
- event의 타입은 React.MouseEvent<HTMLButtonElement> (마우스 클릭일 때)
- onSubmit은 React.ForEvent<HTMLFormElement> 로 바뀜
  - 이벤트 타입을 모르겠을 때는 던지기 전에 e 위에 커서 올리면 나옴
- target을 쓸 때는 currentTarget을 써야 함
  - target은 이벤트의 위치
  - currentTarget은 요소 자체이기 때문

### 리액트 훅

#### useState

- 변수 값을 증가시킬 때, 실제로 증가는 하고 있지만 리액트 돔에서는 그걸 알 수 없어 화면에 그 변수의 값이 증가하는 것을 보이게 하고 싶어도 보여지지 않음(초기에는 출력하지만, 초기 렌더링 후 변경점들은 더 이상 관찰하지 않음, javascript에 관한 것들은)
- 그래서 쉽게 생각하면 리액트 돔이 알 수 있는 변수로 선언해야지만 실제로 출력할 때도 보인다고 생각하면 됨(리렌더링)
- 그래서 리액트 변수라고 쉽게 생각하고 하는 게 useState
- 내부적으로 배열 반환, 내부는 [상태변수, 상태업데이트함수]
  - 그래서 보통 구조분해할당으로 [변수,set변수] 느낌으로 이름 지어주는 것

##### 상태 업데이트

- 첫 번째 방법 : 상태 업데이트에 바로 집어넣는 방법(set변수(값))
- 두 번째 방법 : 콜백 상태로 사용
  - 상태업데이트 내에 화살표 함수 매개변수에 현재 상태값이 들어옴
  - 이름 아무거나 해도 되지만, 보통 콜백함수의 매개변수 이름은 prev로 씀
- 콜백함수로 업데이트를 하고 안 하고차의 차이는 set변수는 비동기 함수라 그냥 () 안에 증가 값을 넣은 코드를 여러 개 써도 하나로 퉁 치지만, 콜백함수를 넣으면 상태 업데이트가 다 되도록 하기 때문에 코드가 다 실행됨, 그래서 현재 상태값과 연관된 값을 바꿀 때에는 콜백 함수를 쓰는 게 좋음
